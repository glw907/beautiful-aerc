- [x] ~~**#65** `RunPush` silent-stop reconnect never backs off~~ `#bug` `#poplar` `#sync` *(2026-08-18, pass 1b round-3 re-review)* (closed 2026-08-18)
  Resolved by pass 1c task 2 (fix round 2, after round 1 was found inert against the shipped transport). The health model keys on proved-ness, not delivery: `pushState.stopped` advances `attempt` on any stop that happens before the stream proves itself past `BackoffMax`, and `proved()` is the only reset. Round 1's `delivered` signal is gone end to end (`stopped`'s parameter, `consumePush`'s tracking) because jmapsource's `OnConnect` queues a notification on every connection (ADR-0018 flush-on-connect), so keying on delivery instead of proving read that connect flush as health and left the escalation dead against the real transport — caught by a new transport-shaped test, `TestRunPushEscalatesOnAConnectFlushDeath`, built on the exact queued-then-closed channel shape `Listen` produces. `RunPush`'s tail `sleepBackoff` call still takes `push.attempt` instead of a fixed `0`. The pinning test that asserted the non-escalating floor, `TestRunPushDoesNotEscalateOnAnUnexplainedStop`, is replaced by `TestPushStateStoppedAdvancesUntilProved` (the escalation/reset contract directly on `pushState`, including that a stop right after proving does not inherit escalation) and `TestRunPushEscalatesOnAnUnprovedStop` (the same curve through `RunPush`, with a deterministic per-gap upper bound). The ADR-0005 poll-fallback timing (`TestRunPushPollsWhileTheStreamStaysRefused`) passed unmodified in both rounds.
  A push stream that opens and dies immediately reopens at `pushState`'s zero-delay floor (`internal/sync/push.go`'s `RunPush`) indefinitely: `pushState.attempt` only advances on a `Listen` failure, and a stream that opens cleanly and then closes at once never produces one, so `reconnect`'s backoff schedule never engages. Measured at ~4 Listen calls/s over a 30-simulated-minute run, ~343k/day for one such server. `TestRunPushDoesNotEscalateOnAnUnexplainedStop` (`internal/sync/push_test.go`) deliberately pins this as the non-escalating floor, so changing it is an owner ruling, not a mechanical fix. Verified fix shape from a scratch experiment: `pushState.stopped` advances `attempt` on a silent stop (not only `fail`), the tail `sleepBackoff` call in `RunPush` takes `push.attempt` instead of a fixed `0`, and both reset on a delivered notification and in `proved()`; this dropped the rate to ~0.1/s. Ruled at the pass 1b gate (Geoff, 2026-08-18): lands in pass 1c, with the pinning test rewritten to assert the new escalation curve.

- [ ] **#42** Native OAuth for Gmail / Outlook IMAP (BYO client ID) `#feature` `#poplar` `#v1` `#config` *(2026-05-10)* — **bundle with #27 first-run wizard**
  Today `internal/mailimap/auth.go` resolves the XOAUTH2 access token from `password-cmd` once at Connect and never refreshes — Gmail/Outlook tokens expire on ~1h timers, so any long-lived session hits `AUTHENTICATIONFAILED` mid-IDLE with no recovery path. The fix isn't "re-invoke password-cmd on auth failure"; the better UX is **native OAuth with BYO client ID**. Mainstream clients (Thunderbird, K-9) ship maintainer-verified OAuth clients, but Google's restricted-scope verification (Gmail IMAP qualifies) requires an annual third-party CASA audit that's not feasible for solo OSS. **aerc's pattern fits poplar**: user registers their own OAuth client in Google Cloud / Azure Portal (one-time, 5–10 min), pastes client ID + secret into config, then poplar handles the browser consent flow, refresh-token storage (encrypted at rest or via `go-keyring`), and proactive refresh before access-token expiry. `password-cmd` stays as the path for self-hosted IMAP, Fastmail JMAP (API token, no OAuth), and users who prefer their own secret manager. Bundles with #27 because the first-run wizard is the natural surface for the OAuth flow ("Sign in with Google" button) and because the wizard's mental model breaks if Gmail/Outlook setup means "go write a helper script." Touches `internal/mailauth/` (OAuth client + refresh loop), `internal/mailimap/auth.go` (cmd/idle goroutines re-resolve on `mail.ErrAuth`), `internal/config/` (`[[account.oauth]]` block with client_id / client_secret / token-store path), `internal/cache/` (refresh token storage + encryption), the wizard flow itself, and the OAuth-setup docs the user follows for BYO registration.
