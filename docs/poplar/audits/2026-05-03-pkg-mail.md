## Special-lens pre-checks

**`mail.ChangeTracker` earning its place?** Yes. Two distinct production
implementations (`mailjmap.Backend`, `mailimap.Backend`) in separate
packages. Cache (`internal/cache/account.go:136`) accepts it as a
separate parameter from `mail.Backend`, enabling independent test fakes.

implemented by both backends but called nowhere through the interface —
only internally within `mailimap/actions.go` as a helper inside `Move`.
`Backend.Search` is implemented but never called through the interface.
Both candidates for removal — flagged below.

**`ErrAuth`/`ErrNotFound` sentinel paths at the cache drainer?** Both
branched on at `internal/cache/drainer.go:142,145`. Earning their place.

  Rationale: `\Recent` is a server-set IMAP flag (RFC 3501 §2.3.2); never set by a client; only reference is one mailjmap test asserting it returns an error, which can be rewritten with any other unsupported value.

- internal/mail/mock.go:29 — 8 — `MockMoveCall` is a Lazy Element declared only as a field of `MockBackend`.
  Action: delete (inline as anonymous struct)
  Rationale: No caller outside the package names or constructs it.

- internal/mail/mock.go:35 — 8 — `MockFlagCall` is a Lazy Element same pattern.
  Action: delete (inline as anonymous struct)
  Rationale: Zero external references confirmed by grep.

- internal/mail/mock_test.go:165 — 2 — `equalUIDs` has exactly one call site (`mock_test.go:137`).
  Action: inline
  Rationale: Six-line helper called once.

- internal/mail/backend.go:44 — 1 — `Backend.Search` is on the interface but is never called through the interface by any consumer.
  Action: refactor (remove from interface; keep concrete method on each backend)
  Rationale: Post-ADR-0121 vestige; backends call their own internal `Search` helpers directly.

- internal/mail/backend.go:46 — 1 — `Backend.Copy` is on the interface but never called through it; `mailimap` uses it internally inside `Move`.
  Action: refactor (remove from interface; `mailimap` can call its own concrete `copyUIDs` helper directly)
