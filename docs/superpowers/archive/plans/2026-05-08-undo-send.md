# Undo Send Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a configurable undo window between Compose Send and dispatch. The user can press `u` within the window to reopen compose with their text intact; otherwise the drainer dispatches normally.

**Architecture:** Schema v10 introduces `outbox.scheduled_for` (user intent, drainer pickup gate) plus `outbox.draft_id` (FK to `drafts`, for compose-restore on undo). Compose Send writes a Draft, queues the outbound row(s) with `scheduled_for = now + undo_window`, and emits `SentMsg{OpIDs, ScheduledFor, DraftID}`. The App reuses `pendingAction` and the chrome banner row with a 1Hz tick for the countdown. `u` calls a new `cache.CancelOps` and reopens compose from the linked Draft. The drainer deletes the linked Draft on dispatch success.

**Tech Stack:** Go 1.26, modernc.org/sqlite, bubbletea/bubbles/lipgloss, table-driven tests, no assertion libraries.

**Spec:** `docs/superpowers/specs/2026-05-08-undo-send-design.md`

package cache

import (
	"context"
	"database/sql"
	"errors"
	"fmt"
	"strings"
)

// ErrNotPending is returned by CancelOps when at least one named
// row has already left OpPending. The cancel is atomic — no row is
// deleted on this error.
var ErrNotPending = errors.New("cache: at least one op is not pending")

// CancelOps deletes the named outbox rows iff every one is in
// OpPending. Used by the undo-send window to revoke a not-yet-
// dispatched outbound. Linked drafts rows are not touched (the
// FK is ON DELETE SET NULL so this would no-op anyway, but the
// caller relies on the draft staying available for compose-restore).
// Empty input is a no-op.
func (a *Account) CancelOps(ctx context.Context, opIDs []int64) error {
	if len(opIDs) == 0 {
		return nil
	}

	tx, err := a.db.BeginTx(ctx, nil)
	if err != nil {
		return err
	}
	defer tx.Rollback()

	placeholders := strings.Repeat("?,", len(opIDs))
	placeholders = placeholders[:len(placeholders)-1]
	args := make([]any, len(opIDs))
	for i, id := range opIDs {
		args[i] = id
	}

	rows, err := tx.QueryContext(ctx,
		fmt.Sprintf(`SELECT id, status FROM outbox WHERE id IN (%s)`, placeholders),
		args...)
	if err != nil {
		return err
	}

	seen := 0
	for rows.Next() {
		var id int64
		var status OpStatus
		if err := rows.Scan(&id, &status); err != nil {
			rows.Close()
			return err
		}
		if status != OpPending {
			rows.Close()
			return ErrNotPending
		}
		seen++
	}
	rows.Close()
	if err := rows.Err(); err != nil {
		return err
	}
	if seen != len(opIDs) {
		// At least one ID didn't match — treat as already-gone, which
		// is conceptually equivalent to ErrNotPending for the caller.
		return ErrNotPending
	}

	if _, err := tx.ExecContext(ctx,
		fmt.Sprintf(`DELETE FROM outbox WHERE id IN (%s)`, placeholders),
		args...); err != nil {
		return err
	}
	if err := tx.Commit(); err != nil {
		return err
	}
	a.signalDrainer()
	return nil
}
```

---
title: Undo-send via outbox.scheduled_for + draft-linked rows
status: accepted
date: 2026-05-08
---

## Context

BACKLOG #35 splits across two passes; 10a delivers the headline
short-window undo. The cache outbox already has next_eligible_at
for drainer backoff; we needed a separate user-intent timestamp
that survives transient retries and renders stably in the UI.
We also needed a way to give the user their text back when they
press u — undo without restoration is worse-than-Pine UX.

## Decision

Schema v10 adds outbox.scheduled_for (unix nanos, user intent,
mutated only by user action) and outbox.draft_id (FK to drafts
with ON DELETE SET NULL). The drainer pickup gate becomes
`now >= COALESCE(scheduled_for, 0) AND now >= COALESCE(next_eligible_at, 0)`.
Compose Send persists a drafts row, queues the outbound row(s)
with scheduled_for and draft_id, and emits SentMsg{OpIDs,
ScheduledFor, DraftID, Draft}. The App reuses the existing
pendingAction + chrome banner with an added 1Hz tick to render
the countdown. u routes by op kind: triage runs the inverse
Cmd (existing); send-undo calls a new cache.CancelOps and
reopens compose from the in-memory Draft. The drainer deletes
the linked drafts row inside the OpDone transaction.

CancelOps is atomic across one or two rows because IMAP
outbound is two ops (Send + Append-to-Sent) that the user
thinks of as one action.

## Consequences

- Pass 10b's reschedule + edit-as-draft both build on these
  primitives without further schema work.
- Backoff and user holds are orthogonal — a transient failure
  during a hold can never overwrite the user's intended send
  time.
- The drainer success path now spans two writes (status flip +
  draft delete) and runs in a transaction; non-Send/Append kinds
  pass empty draft_id and pay only one extra string compare.
- A crash between Send and dispatch leaves an orphan drafts row
  if the outbox row was already inserted. The next Pass 10b
  reconcile pass can sweep these; for 10a the row is harmless
  (user can delete from the drafts list).
```
