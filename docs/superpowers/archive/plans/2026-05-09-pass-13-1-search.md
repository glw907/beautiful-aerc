# Pass 13.1 — Search (#38)

## Goal

Cross-folder search reading from the local body cache that
Pass 13's `Backfiller` populates. Sidebar search shelf grows a
scope toggle and an operator parser; results render in the
right pane via the existing messagelist when scope is
cross-folder.

## Settled (carried in from STATUS + brainstorm)

- **Index.** SQLite FTS5 — no Bleve, no external index. Schema
  v11 adds a contentless virtual table
  `messages_fts(subject, from_addr, to_addr, cc_addr, body,
  content='')` with `rowid = messages.id`. Contentless because
  external-content + triggers can't extract MIME body text in
  pure SQL — we'd need Go in the loop either way, so we own
  the writes ourselves.
- **Index update.** Inside the existing `upsertMessages` and
  `storeBody` transactions; no SQLite triggers. Header upsert
  writes subject/from/to/cc; storeBody extracts plain text via
  a new `content.ExtractPlainText(mime []byte) (string, error)`
  and writes the body column. Pattern: `DELETE FROM messages_fts
  WHERE rowid = ?; INSERT INTO messages_fts(rowid, ...) VALUES
  (?, ...)` for atomicity (FTS5 lacks UPSERT but supports
  per-column UPDATE — body-only writes use UPDATE).
- **Operators.** `from:`, `to:`, `cc:`, `subject:`, `in:folder`,
  `has:attachment` (mapped to `attachments` table existence).
  Bare terms match subject + body + from + to (survey synthesis
  recommendation). Quoted phrases supported. Parser is pure:
  `internal/search/parser.go` returns `Query{Terms, From, To,
  Cc, Subject, In, HasAttachment}`. The current sidebar
  `[name]/[all]` mode badge is retired — operators subsume it.
- **Scope toggle.** `\` toggles folder-local ↔ cross-folder
  while typing. `Tab` retires from the search shelf. Sidebar
  shelf info row shows `[folder]` / `[all folders]` (replacing
  the old mode badge slot). Folder-local mode keeps current
  hide-and-filter behavior; cross-folder swaps the right pane
  to a results-mode messagelist.
- **Sort.** `sent_at DESC`, no toggle. Matches Geary, K-9,
  aerc, Apple Mail, Outlook, Fastmail. Geary precedent —
  hardcoded, no-config — fits poplar's stance.
- **Origin folder display.** Cross-folder rows render `[Inbox]
  Alice  Project update` — folder name as a styled prefix in
  the sender column. Matches Geary badge / Gmail label /
  Fastmail prefix; collapses cleanly in Spartan tier (the
  sender column is the only column there).
- **Throttle warn.** Extend `BackfillProgress() (done, total
  int, warn bool)`. `warn = true` while the Backfiller is in
  throttle backoff (i.e., `throttleAttempts > 0`). The warn
  field already plumbed through `SetBackfill(done, total,
  paused, warn)` in Pass 13 but always passed `false`; this
  pass surfaces the real value.
- **Initial backfill on migration.** v11 also populates
  `messages_fts` from existing `messages` rows in the same
  transaction (header columns only — body fills as Backfiller
  runs and storeBody fires).

## Open — none

The starter prompt's four open questions are settled above
plus in the brainstorm exchange (sort, origin display,
scope toggle).

## Tasks

1. **Schema v11 + FTS5 virtual table.** `migrateV11` creates
   `messages_fts` (contentless, subject/from_addr/to_addr/
   cc_addr/body) and backfills header columns from existing
   `messages` rows in the same transaction. Body column stays
   empty until storeBody fires. Tests: schema_test verifies
   v10→v11 round-trip and that backfill populates header
   columns for fixture rows.
2. **`content.ExtractPlainText(mime []byte) (string, error)`.**
   Factor out the MIME→plaintext path currently inlined in
   `internal/ui/account/cmds.go` (lines 183–249) into a pure
   helper in `internal/content/plaintext.go`. Returns text/plain
   when present; falls back to text/html stripped via the
   existing `goldmark`/strip path used by viewer. UI cmd
   delegates to the helper. Tests: table-driven against
   testdata MIME fixtures (text-only, html-only, multipart/
   alternative).
3. **FTS write hooks.** `upsertMessages` writes header columns
   to `messages_fts` inside its existing transaction — DELETE
   by rowid, INSERT all five columns (body pulled from current
   `bodies` row if present, else empty). `storeBody` runs
   `UPDATE messages_fts SET body = ? WHERE rowid = ?` after
   `ExtractPlainText` succeeds; on extraction failure the
   body column stays unset and a debug log fires (we don't
   block the body store on indexing errors). Tests: integration
   test that header upsert + body store leaves the row queryable
   via `MATCH 'subject_term'` and `MATCH 'body_term'`.
4. **Operator parser.** `internal/search/parser.go` —
   `Parse(query string) Query`. Tokenizes on whitespace,
   honors quotes, recognizes `from:`, `to:`, `cc:`, `subject:`,
   `in:`, `has:attachment`. Unknown `key:value` falls through
   as a bare term. Empty query → zero `Query`. Pure, no I/O.
   Table-driven tests covering each operator + quoted phrases +
   mixed bare/operator.
5. **Cache `Search` query.** `(*Account).Search(ctx,
   q search.Query, scope SearchScope, limit int) ([]SearchHit,
   error)`. `SearchScope` is `Folder string` (folder name; `""`
   = cross-folder). `SearchHit` carries `mail.MessageInfo` plus
   `Folder string` (origin name, populated only when scope is
   cross-folder). Implementation: builds an FTS5 MATCH string
   from `Query.Terms` (bare match across all columns) plus
   per-field column filters for operator subsets (`from:` →
   `from_addr MATCH 'term'`); folder filter via JOIN to
   `message_mailboxes` + `folders`; `in:` operator pre-filters
   the same way; `has:attachment` joins to `attachments`. Sort
   by `messages.sent_at DESC LIMIT ?`. Folder-scope path skips
   the cross-folder JOIN. Tests: per-operator integration
   tests against a seeded fixture cache.
6. **Backfiller throttle warn signal.** Add atomic
   `throttling bool` (or derive from `throttleAttempts > 0`
   under the existing mutex) on `Backfiller`. Extend
   `BackfillProgress()` signature to
   `(done, total int, warn bool)`. `App.refreshBackfillSegment`
   reads the new return and passes through to
   `SetBackfill(done, total, paused, warn)` — drop the
   hardcoded `false`. Update existing call sites + tests.
7. **Sidebar shelf rewire.** `internal/ui/sidebar/search.go`:
   retire `searchCycleMode` (Tab handler) and the
   `uicore.SearchMode` enum (or narrow it to `Scope`). Add a
   `SearchScope` enum (`ScopeFolder` / `ScopeAll`) and
   `searchToggleScope` binding on `\`. The `[name]/[all]` mode
   badge becomes a `[folder]/[all folders]` scope badge. Update
   `SearchUpdatedMsg` to carry `Scope` instead of `Mode`.
8. **AccountTab cross-folder mode.** When `SearchUpdatedMsg`
   arrives with `ScopeAll` and a non-empty query, AccountTab
   issues a search Cmd
   (`searchCmd(query, ScopeAll) → searchResultsMsg`). Results
   feed `messagelist.SetSearchResults([]SearchHit)` and a flag
   that swaps the right pane. `ScopeFolder` keeps the current
   `SetFilter` path. Folder selection via `J/K` is inert while
   results pane is active (selecting a folder commits the
   search and exits cross-folder mode). Esc / clear restores
   the prior folder + cursor.
9. **Messagelist results mode.** `(*Model).SetSearchResults(
   hits []cache.SearchHit)` switches the model into a
   results-display mode: threading off, sort taken from hit
   order (already `sent_at DESC` from the query), origin folder
   rendered as `[<Folder>] ` styled prefix in the sender slot
   via a new `Styles.SearchOriginBadge` lipgloss style
   (`AccentSecondary` foreground, `SidebarBg` background).
   `ClearSearchResults` returns to the prior `SetMessages`
   source. Triage Cmds receive the origin folder via
   `ActionTargets()` extension — rows in results mode carry
   their folder so triage routes to the right `cache.QueueOp
   (folder, uid, args)`.
10. **Tests + tmux verify.** Unit tests cover items 1–9
    inline. Live tmux capture at 80×24 (Spartan) and 120×40
    (Full) for: idle shelf (no change), typing in folder
    scope (existing behavior preserved), typing in cross-
    folder scope with `from:alice` operator returning hits
    from Inbox + Archive (origin badge visible), throttle-warn
    backfill segment showing `↓ ⚠` while paused under load.
