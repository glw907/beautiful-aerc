# Audit B.1 — Elm + bubbletea v2 conformance

**Date:** 2026-05-12  
**Pass:** 30  
**Audit phase:** B.1 (per `docs/poplar/audit-plan.md`).

Walked every `internal/ui/`, `internal/catkin/`, and
`internal/ui/wizard/` source against the Elm rules from
`elm-conventions` and the v2 idioms in
`docs/poplar/bubbletea-conventions.md` §10. Recording what was
looked at, not just what was found.

## Focuses walked

1. **Receiver discipline.** `rg 'func \(\w+ \*\w+\)'` across each
   subpackage; cross-checked against the value-Update / value-View
   signatures the focus list names.
2. **Cmd-as-only-IO.** `rg 'backend\.|os\.Open|os\.Create|exec\.|http\.|os\.WriteFile'`
   across the tree; spot-checked each hit for "is this inside a
   `tea.Cmd` closure or inline in `Update`."
3. **Msg vocabulary discipline.** Walked each subpackage's
   `msgs.go` against parent-side consumers in `internal/ui/app_*.go`.
4. **Size contract.** `rg 'WindowSizeMsg|SetSize'` against the
   parent fan-out at `account/model.go:125-157` and per-child
   `Update` arms.
5. **`JoinHorizontal` ban under SPUA-A.** `rg
   'lipgloss\.(JoinHorizontal|JoinVertical)'` then audited every
   site for "does this row carry SPUA-A icons?"
6. **Cursor hoist.** Walked every `textinput.New` / `textarea.New`
   call and confirmed `SetVirtualCursor(false)` follows.
7. **Paste routing.** Confirmed ADR-0189b contracts: address-field
   atomic chip emission, catkin URL-wrap. No new paste arms outside
   `compose.Model` / `catkin.Model`.
8. **`bubbles/v2/<pkg>` analogue preference.** Pass 27–29
   introduced no new UI surfaces; the deviation ADRs (0194, 0195,
   0199, 0200, 0201) match the live code.
9. **Deviation ADRs current.** Same walk; all five accepted, no
   drift against current implementations.

## Findings

### F1 — Pointer-receiver mutators across UI subpackages [P1, ROADMAP]

Pass 27 converted **catkin** to all-value (ADR-0212) and Pass 28
deleted the `mailcompose.Editor` adapter (ADR-0213). Every other
UI subpackage still ships the same straddle catkin had pre-27:
value `Update` / `View` for the Elm contract, but state mutates
through pointer-receiver methods called by the parent.

The hits per subpackage (pointer mutator counts, omitting cache /
init helpers):

- `internal/ui/messagelist/model.go`: 22 `*Model` methods
  (`SetMessages`, `SetSize`, `SetLayout`, `ToggleFold`,
  `ToggleMark`, `EnterVisual`, `ExitVisual`, `RefreshSource`,
  `MoveCursor`, …); value `Update` and `View`.
- `internal/ui/sidebar/model.go`: 9 `*Model` methods
  (`SetFolders`, `SetOutboxCount`, `ToggleExpanded`, `SetSize`,
  `SetLayout`, `SelectByCanonical`, …) plus `*Search` mutators.
- `internal/ui/account/model.go`: value `Update` / `View`, but
  10 pointer dispatch helpers (`dispatchTriage`, `queueMove`,
  `queueFlag`, `dispatchMove`, `dispatchMoveFromPicker`,
  `pageFor`, `maybeLoadMore`, `maybeRetentionSweep`,
  `dispatchEmpty`, `SetOutboxCount`).
- `internal/ui/reader/model.go`: value `Update` / `View` /
  `SetSize`, but a pointer-receiver `layout()` that mutates
  the value-receiver local.
- `internal/ui/compose/model.go`: **entirely pointer-receivered**,
  including `Init`, `Update` (returning `*Model`), `View`. The
  one outlier in the tree.
- `internal/ui/contacts/{popover,list,sidebar,form}.go`: pointer
  mutators on `*Popover`, `*List`, `*Sidebar`; `Form` mostly
  value.
- `internal/ui/outbox/model.go`: `SetSize`, `SetRows` on `*Model`.
- `internal/ui/wizard/section_*.go`: every section type is
  pointer-receivered top-to-bottom.

This is not a bug. The straddle works because Update's value
receiver always wraps the pointer mutators run by the parent, but
it forecloses the same reasoning gains that motivated ADR-0212 for
catkin (immutable snapshot for tests, value diffs in Update, no
hidden aliasing).

Disposition: file as a ROADMAP project ("internal/ui/ all-value
path"). Convert one subpackage per follow-up pass — `messagelist`
first (highest mutation density), then `sidebar`, then `compose`
(largest), then the rest. Each conversion is its own ADR.

### F2 — `writeConfig` runs file I/O inline in `Update` [P0, fix inline]

`internal/ui/wizard/section_confirm.go:61` calls `writeConfig`
synchronously from `Update` on form completion. `writeConfig`
performs:

- `os.MkdirAll(dir, 0o700)`
- `os.Stat(path)` — guards against overwriting existing config
- `os.CreateTemp(dir, ...)`
- `tmp.Write(body)` / `tmp.Sync()` / `tmp.Close()`
- `os.Chmod(tmpPath, 0o600)`
- `os.Rename(tmpPath, path)`

Six syscalls inline in `Update`. The user has paused for input so
the latency cost is academic, but the rule from Elm Rule 3 is
absolute: blocking I/O lives inside `tea.Cmd`. Same lens
elsewhere flagged catkin pre-27 and the cache drainer pre-Pass-12;
the wizard slipped through because its blocking work runs once at
form-completion.

Disposition: P0. Move the write to a `writeConfigCmd` that returns
either `FinishMsg{Path}` or an `ErrorMsg`. The error path can keep
its current shape (`s.err = err`); the Cmd returns a typed
`writeConfigDoneMsg{Path, Err}` and `Update` flips state when it
arrives.

### F3 — Catkin's wrapped textarea never calls `SetVirtualCursor(false)` [P0, fix inline]

ADR-0189b's Decision section claims: *"every textinput/textarea
calls `SetVirtualCursor(false)`"*. That's literally true for
every textinput/textarea constructed in `internal/ui/`, but
**not** for `internal/catkin/catkin.go:49` which constructs the
wrapped textarea via `textarea.New()` and hands it to `NewBuffer`
without the call.

The reason it doesn't matter in practice: catkin owns its own
render path (`internal/catkin/render.go`) and never calls
`b.ta.View()`. The textarea's virtual cursor would only paint into
output if textarea's `View()` were rendered, which it isn't. So
the bug is *invariant-rot*, not a visible regression — but the
ADR claim is wrong as stated, and that's the higher-cost failure
mode (a future audit assumes the claim and skips re-checking).

Disposition: P0. Add `ta.SetVirtualCursor(false)` inside
`catkin.NewBuffer`. One line; restores the ADR-0189b literal.

### F4 — `WindowSizeMsg` not forwarded into embedded bubbles components [P0, fix inline]

The audit checklist (`bubbletea-conventions.md` §10): *"`WindowSizeMsg`
is forwarded into children after the parent stores dims and calls
`SetSize`."* The poplar tree partially honors this:

- `account.Model.updateTab` (`internal/ui/account/model.go:155`)
  forwards `WindowSizeMsg` into `m.viewer.Update(msg)`. ✓
- `account.Model.updateTab:145` forwards into the sidebar search
  shelf. ✓
- `reader.Model.Update` (`internal/ui/reader/model.go:199-213`)
  matches only `spinner.TickMsg` and `tea.KeyPressMsg`;
  `WindowSizeMsg` falls through the default `return v, nil`. The
  embedded `viewport.Model` therefore never sees the message.
  Reader's `SetSize` re-runs `layout()` which **reconstructs**
  the viewport via `viewport.New(...)`. The reconstruction is
  effectively a hard reset — it works, but it's the wrong shape;
  scroll position drops on every resize.
- `messagelist.Model.Update` (`model.go:190`) matches only
  `tea.KeyPressMsg`; `WindowSizeMsg` falls through. The embedded
  `bubbles/v2/list.Model` therefore never sees the msg. The list's
  `SetSize` is called via `messagelist.SetSize`, but the bubbles
  list documents that paginator state ride on `WindowSizeMsg`.
- `sidebar.Model.Update` is a self-contained dispatch — no embedded
  bubbles component below. ✓
- `compose.Model.Update` propagates window dims via `SetSize`
  applied to the embedded catkin / attach-picker / schedule-picker
  components. Catkin owns its render; no upstream bubbles
  component needs the msg directly. ✓

Disposition: P0. Add `case tea.WindowSizeMsg:` arms to
`messagelist.Model.Update` (forward into `m.list`) and to
`reader.Model.Update` (forward into `v.viewport`). Reader keeps
its `SetSize`-driven layout reconstruction for content sizing;
the forward gets viewport's internal state in sync.

## What was *not* found

- No `len()` for layout math (`rg 'len\('` in render/width
  contexts: zero).
- No state mutation in `View()` (per-Model `View()` body grep).
- No new `JoinHorizontal` calls on SPUA-A rows (every hit either
  predates Pass 17 or carries no SPUA-A icons — wizard preview,
  reader vertical stack).
- No v1-only API leaks (`HighPerformanceRendering`,
  `tea.Sequentially`, etc.). One match for `NewModel` —
  `wizard.NewModel` — is a poplar-defined constructor, not the
  bubbles v1 form.
- No `msg.String()` switches on actionable keys (zero hits).
- No `lipgloss.AdaptiveColor` or `compat.AdaptiveColor`.
- No per-input `cursor.Model` survivals.
- No imperative chrome Cmds (`tea.EnterAltScreen`, etc.).
- All five deviation ADRs (0194, 0195, 0199, 0200, 0201) describe
  the live code accurately.
