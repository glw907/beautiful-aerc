# Pass 18 — Polish II

**Status:** in progress
**Theme:** chrome polish + dim-semantics narrowing + showcase-before-freeze bubble-shape cleanup.

## Goal

Close BACKLOG #14 (popover dim) by narrowing dim semantics across
the whole UI: **dim means "not yet wired" — nothing else.** Sweep
five small adjacent items surfaced during 10–17c.

## Scope

`internal/ui/` only. No backend, cache, or wire-format changes.

## Settled before coding

- **Underlay dim retires entirely.** Today every overlay branch in
  `App.View()` calls `uicore.DimANSI(frame)` and composites the
  overlay on top of the dimmed frame (12 call sites). This
  overloads dim with two meanings: (a) "modal is active" and
  (b) "this binding isn't wired yet" (ADR-0072 wired/unwired in
  the help popover). Collapsing to (b) only makes the visual
  language tight: bright = live, dim = unimplemented. The overlay
  box itself is already the "modal active" cue.
- The pre-beta refactor pass after Polish II owns #46 (messagelist
  iter.Seq2 walk), #43 (drop `Date string` legacy fallback), #44
  (compose package collision rename), #47 (Levenshtein
  consolidation), and #12 (tidy → tidytext rename). All must land
  before v0.9.0 freeze.

### 2. #48 — commandFooter ellipsis truncation

`fitFooterHints` (in `internal/ui/footer.go`) silently drops
hints when the width is too narrow. When at least one hint was
dropped, append a `…` marker before the trailing pad so users
know more hints exist at wider widths. Bubbles v2 help's
`shouldAddItem` is the carry-forward source; we lift the
algorithm (the ellipsis-on-truncate idea), not the package
(ADR-0200 forecloses adoption).

Implementation: `fitFooterHints` returns `(visible [][]hint,
truncated bool)`; `renderGroups` appends ` …` (styled
`FooterHint`) when `truncated`. Width budget the ellipsis into
the drop loop so the marker itself fits.

### 3. #45.1 — `helppopover.View` zero-arg

`helppopover.Model.View(width, height int)` → `View()`. Cache
size in existing `SetSize`. Production already uses
`Box`/`Position`/`PlaceOverlay`; only tests call `View`, which
should now read the cached size.

### 4. #45.5 — export `KeyMap` across subpackages

Today only `account.Keys`, `messagelist.KeyMap`, `sidebar.KeyMap`
are exported. Promote:

- `compose`: `composeKeys` → `KeyMap`, `attachPickerKeys`
  (compose-side) → `AttachPickerKeyMap`, `dropdownKeys` →
  `DropdownKeyMap`
- `reader`: `viewerKeys` → `KeyMap`, `linkPickerKeys` →
  `LinkPickerKeyMap`, `attachPickerKeys` → `AttachPickerKeyMap`
- `movepicker`: `modelKeys` → `KeyMap`

`internal/ui/`-level keymaps (`confirmKeys`, `conflictKeys`,
`outboxKeys`) stay unexported — they live next to the App and
aren't subpackage seams.

### 5. #30 — sidebar.Model.View render cache

`sidebar.Model.View()` rebuilds 60–80 lipgloss renders per
`tea.Msg`. Apply the `*<T>Cache` pointer + dirty-flag pattern
from `movepicker`, `helppopover`, `ConflictOverlay`. Dirty bits
set by `SetFolders` / `SetSize` / `SetLayout` / `SetOutboxCount`
/ `MoveToTop` / `MoveToBottom` / `SelectByCanonical` / cursor
moves through `Update`.

Note ADR-0130 caveat: sidebar churns more than the other cached
overlays (per-tick spinner-active redraws were the original
concern). The dirty flag handles this correctly — render is
stable between explicit mutations.
