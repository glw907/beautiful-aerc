## Findings — Focus 1 (mail-infra)

### F1.1 — JMAP network errors fall through unclassified

`mailjmap/errors.go:21-35`. `classifyErr` handles
`*jmap.RequestError` 401/403/404 but has no branch for plain
`net.Error` / `*url.Error` / `io.EOF` wrappers from `go-jmap`'s
HTTP transport. Result: JMAP transport drops never reach
`mail.ErrConnection`; the `pumpUpdatesCmd` reconnect lens stays
dark on JMAP (only the push loop's own `ConnReconnecting` emit
covers it). No data loss — the drainer's `default` arm routes to
backoff retry, which is correct — but the sentinel gap is real.
**BACKLOG #54.**

### F1.2 — mailimap Destroy Gmail branch leaves `b.current` stale

`mailimap/actions.go:95-105`. Gmail `Destroy` issues
`cmd.Select(trash, false)` to switch the selected mailbox, but
`b.current` is not updated. Window: between the `Select(trash)`
and the next explicit `OpenFolder`, any cmd-path action that
triggers a redial will re-Select the *pre-Destroy* folder and
address the wrong mailbox. Narrow, but the invariant is broken.
**BACKLOG #56.**

### F1.3 — mailjmap holds `b.mu` across HTTP round-trip

`mailjmap/jmap.go:316-324`. `refreshFoldersLocked` is called with
`b.mu` held and itself calls `fetchFolders(b.client, b.session)`
→ `b.client.Do(req)`. Any goroutine that needs `b.mu` (emit,
readers, push loop's `handleStateChange`) blocks for the
duration of the network round-trip. Latency stall, not data
loss. Pattern is asymmetric with the IMAP-side redial refactor,
which kept dial paths lock-free. **BACKLOG #55.**

### F1.4 — drainer `ErrConnection` routing is implicit

`cache/drainer.go:136-167`. `mail.ErrConnection` is not a named
case in `executeOne`'s conflict matrix; the `default` arm
correctly routes it to transient retry. No code change required,
but the absence of a negative test or comment means a future
refactor could mis-route it. Fold into the next pass that
touches `executeOne`. **Inline fix; no BACKLOG entry.**

## Findings — Focus 2 (config validator)

### F2.0 — No strict-mode TOML decoding (typo hazard)

All four `toml.Unmarshal` sites (`accounts.go:366`,
`ui.go:155`, `cache.go:57`, `writer.go:111`) use
`github.com/BurntSushi/toml` with default permissive decoding.
Unknown keys are silently dropped: `passwrd = "tok"` or
`starttsl = true` leaves the intended field at its zero value
with no error. Highest-leverage fix in the config layer — one
decoder configuration change closes every typo-of-adjacent-field
hazard across the file. **Folded into BACKLOG #57.**

### F2.1 — `oauth-store` enum not validated

`accounts.go:544`. Only `"keyring"` and `"age-file"` are
meaningful; any other string defers the error to first token-
store open. **Folded into #57.**

### F2.2 — `auth` / `smtp.auth` enum not validated

`accounts.go:421`. Known set: `plain`, `login`, `cram-md5`,
`xoauth2`, `bearer`. A typo (`oauth2` for `xoauth2`) defers the
error to SASL handshake. **Folded into #57.**

### F2.3 — `contacts.url` empty error text is misleading

`accounts.go:67-69`. Empty URL surfaces as `"url: not parseable"`;
the message should say "url: required". **Folded into #57.**

### F2.4 — `port = 0` not validated for bare `provider = "imap"`

`accounts.go:493-500`. Host is validated, port is not. A non-
preset IMAP account without a port surfaces a runtime dial error
rather than a config error. **Folded into #57.**

### F2.5 — Contacts credentials not validated when fallback fails

`accounts.go:586-597` (`finalizeContacts`) and `:63-89`
(`validate`). After fallback from the parent account, neither
`Password` nor `PasswordCmd` may be set; the failure surfaces as
a CardDAV 401, not a config error. **Folded into #57.**
