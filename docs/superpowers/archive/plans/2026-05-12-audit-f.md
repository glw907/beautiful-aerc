# Audit F — sharp edges and insecure defaults

Phase F of `docs/poplar/audit-plan.md`. Read-only walk of every
package in `internal/` and the cobra wiring in `cmd/poplar/`
against the Trail-of-Bits sharp-edges / insecure-defaults lens:

> Does the codebase ship config defaults, API surfaces, and
> convenience helpers whose easy path is the wrong path?

The bias the lens targets: LLMs prefer "looks helpful," which
produces convenience methods that obscure failure modes and
config defaults tuned for the example case rather than the
production case.

## Rubric

Each finding tagged P0/P1/P2 per audit-plan §"Audit mechanics":

- **P0** — silent data loss, credential leak, behavior the user
  cannot recover from without restart. Blocks the next audit
  phase; queue a remediation sub-pass immediately.
- **P1** — behavioral hazard, real user-visible failure, queued
  for the remediation sub-pass.
- **P2** — note-only, log to BACKLOG or fold into a later pass.
- **already-addressed** — finding agent surfaced something that
  a later ADR or pass already fixed; record so future audits
  don't re-surface.

## Focuses (audit-plan §"Phase F")

1. **Boolean config fields.** For each, name which default is
   example-friendly and which is production-safe. Flag every
   disagreement where the default is the wrong side. Examples
   in scope: `insecure-tls`, debug toggles, retry caps,
   timeouts, fallback-on-error switches.
2. **Boolean parameters on exported functions.** Each is a
   footgun candidate; ask what `f(x, true)` means at the call
   site without the signature in view.
3. **Optional fields with magic defaults.** Zero means
   "unlimited," nil means "stdlib's default." Each is a
   documentation dependency; documentation rots first.
4. **Ignored returns.** `_ = x.Close()`, `_, _ = w.Write(...)`.
   Some are correct (deferred close, intentional drop); others
   are silent error suppression. Walk every site.
5. **Permissive failure paths.** `if err != nil { log.Warn();
   return nil }` and variants. The error-banner discipline
   (ADR-0073) ensures errors *can* surface; this lens checks
   they *do*.

## Walk strategy

Per-package parallel dispatch. Four agents, each walking a
cluster:

- **Batch 1 — Mail stack:** `mail`, `mailauth`, `mailimap`,
  `mailjmap`, `mailcompose`
- **Batch 2 — Storage & content:** `cache`, `search`, `content`,
  `contacts`, `filter`
- **Batch 3 — UI layer:** `ui` (all subpackages), `catkin`,
  `ansix`, `theme`, `tidytext`, `icalendar`
- **Batch 4 — Config / CLI / utilities:** `config`, `wizard`,
  `term`, `strdist`, `cmd/poplar`

Each agent produces a finding list with rubric tags. Aggregation
+ ADR write happen in this plan doc and ADR-0228.

## Out of scope

- Re-running phases A/B/C/D/E focuses. Those returned empty (or
  remediation-passes addressed P0/P1s); their lenses are not
  Phase F's lens.
- Test-assertion meaningfulness — that's Phase G.
- Voice / documentation rot — that's Phase Final.
- Fixing findings inline. Findings here produce a remediation
  sub-pass (39.1) if any P0/P1 land; P2s land in BACKLOG.

Dispatched in four parallel batches by package cluster. Tally:

| Batch | Packages | P0 | P1 | P2 |
|-------|----------|----|----|----|
| 1 — mail stack | mail, mailauth, mailimap, mailjmap, mailcompose | 0 | 3 | 4 |
| 2 — storage & content | cache, search, content, contacts, filter | 0 | 2 | 1 |
| 3 — UI layer | ui (+subpkgs), catkin, ansix, theme, tidytext, icalendar | 0 | 2 | 5 |
| 4 — config / CLI | config, wizard, term, strdist, cmd/poplar | 0 | 2 | 3 |
| **total** | 21 packages | **0** | **9** | **13** |

F-batch3-2 (compose pointer receivers) demoted P1→P2 on re-triage
(structural footgun, no current bug). Final: 8 P1, 14 P2, 0 P0.

The cluster shape is striking: the dominant sharp-edge pattern is
not insecure config defaults but **`_ =` error suppression on
write-back / terminal-state paths**. ADR-0073's "errors must
surface" has a discipline gap on the drainer and cache write-back.
The audit-plan §"Phase F" lens correctly weighted "ignored returns"
and "permissive failure paths" alongside the boolean / default
focuses.
