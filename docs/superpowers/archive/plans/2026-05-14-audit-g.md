# Audit G — test assertion meaningfulness

Phase G of `docs/poplar/audit-plan.md`. Read-only walk of every
`*_test.go` under `internal/` and `cmd/poplar/` against the lens:

> For each test in the suite, what would have to be wrong about
> the code under test for the test to fail? If the answer is
> "nothing realistic," the test is theatre.

The empirical bias the lens targets: LLMs reliably write tests
that pass syntax but verify nothing. Coverage rises; correctness
doesn't. The Audit Final test-infrastructure lens covers *fakes
that obscure*; this phase covers *assertions that don't assert*,
which is the larger surface.

## Rubric

Each finding tagged P0/P1/P2 per audit-plan §"Audit mechanics":

- **P0** — test would survive a behavior-breaking bug in
  production code (silent regression channel). Blocks the next
  audit phase; queue a remediation sub-pass immediately.
- **P1** — assertion meaningfully degraded: tautological,
  derives expected from the same code path, no error-branch
  coverage on a function with an error path, or a fake's
  unhappy path is silent-success.
- **P2** — note-only: shape would catch obvious bugs but is
  weaker than it should be; fold into a later pass or BACKLOG.
- **already-addressed** — finding agent surfaced something that
  a later ADR or pass already fixed; record so future audits
  don't re-surface.

## Focuses (audit-plan §"Phase G")

1. **Trivially-passing assertions.** Every `Test*` in `internal/`
   and `cmd/poplar/`. For each, name the property it asserts.
   "Function returned," "no panic," "result is non-nil," "no
   error" on a function with no error path — tells.
2. **Self-derived expectations.** Tests where the expected value
   is computed by the same code under test (test and implementation
   wrong together; both pass). Look for expectations computed
   from the input via a helper that's also exercised by other
   tests.
3. **Unread goldens.** Snapshot / golden tests where the golden
   was committed without inspection — drainer FSM transitions,
   renderer fixture frames, ConfigError messages. For each, was
   the golden read end-to-end before commit, or accepted because
   the diff was green?
4. **Silent-success fakes.** A `fakeBackend.Send` that returns
   nil unconditionally is the MockBackend hazard at test scope.
   Every fake method whose unhappy path is "return nil" is a
   finding.
5. **Missing error-branch coverage.** Happy-path-only tests on
   functions whose contract includes a typed sentinel
   (`mail.ErrAuth`, `mail.ErrConnection`, `mail.ErrNotFound`,
   `*config.ConfigError`, `cache` constraint violations).

## Walk strategy

Per-package parallel dispatch matching Audit F's cluster shape.
Four agents, each walking a cluster:

- **Batch 1 — Mail stack:** `mail`, `mailauth`, `mailimap`,
  `mailjmap`, `mailcompose`
- **Batch 2 — Storage & content:** `cache`, `search`, `content`,
  `contacts`, `filter`, `icalendar`
- **Batch 3 — UI layer:** `ui` (all subpackages including
  `account`, `compose`, `contacts`, `helppopover`, `messagelist`,
  `movepicker`, `outbox`, `reader`, `sidebar`, `uicore`,
  `wizard`), `catkin`, `ansix`, `theme`, `tidytext`
- **Batch 4 — Config / CLI / utilities:** `config`, `wizard`
  (internal/wizard), `term`, `strdist`, `cmd/poplar`

Each agent produces a finding list with rubric tags. Aggregation
+ ADR write happen in this plan doc and ADR-0230.

## Out of scope

- Re-running phases A/B/C/D/E/F focuses.
- Fixing findings inline. Findings here produce a remediation
  sub-pass (40.1) if any P0/P1 land; P2s land in BACKLOG.
- Adding new tests for uncovered code paths. The lens is "do
  existing tests assert anything"; gap analysis is Phase Final.

## Disposition

Per audit-plan §"Audit mechanics": **0 P0** means the soak gate
remains intact. **21 P1** queue for Pass 40.1 — the largest
remediation queue of the audit cycle so far (vs Audit F's 8 P1).
The Audit F precedent applied (P1s queue for remediation, P2s
land in BACKLOG or fold into later passes).

The dominant signal — silent-success fakes — is structural: the
project's standing fakes (`MockBackend`, `fakeClient`,
`blockingBackend`, `fakeCache`) were built for happy-path
construction tests and never grew error-injection seams. The
fix shape is uniform: extend each fake with per-method error
fields (`SendErr error`, `MoveErr error`, …) consulted on call.
The trivially-true lipgloss-style assertions are a separate
mechanical cluster — fix shape: assert `GetForeground()` returns
the expected color value, not `Render() != ""`.

The findings, rationale, and aggregate tally land in ADR-0230;
this plan archives at pass-end.
