## Context

Pass 20 cuts `v0.9.0`. After tag, poplar enters beta soak: data
formats are frozen, and the only landings are bug-fix releases
until v1.0. ADR-0105 codifies the release model.

The pass has four deliverables:

1. **README** — the GitHub landing-page artifact. Today there is
   none. Without one, an evaluator hitting the repo has no idea
   what poplar is.
2. **LICENSE** — the repo ships with no `LICENSE` file. Required
   before tag.
3. **Docs sweep** — `docs/poplar/` has stale references from the
   Pass 19 renames (`internal/compose` → `internal/mailcompose`,
   `internal/tidy` → `internal/tidytext`) and the dropped
   `MessageInfo.Date string` field. Invariants is current
   (Pass 19 updated it), but ADRs, audits, and research docs
   carry the old names.
4. **BACKLOG reconciliation** — entries #43 (drop `Date string`),
   #44 (rename `internal/compose`), and #12 (rename
   `internal/tidy` → `internal/tidytext`, drop CLI machinery)
   all landed in Pass 19 but are still open in BACKLOG.md. Close
   them with the resolution note.

The first three are user-visible at tag; the fourth is hygiene
so the post-tag backlog reads accurately.

The starter prompt asked two questions:

- **Apply #44 in this pass or defer?** Moot — #44 already shipped
  in Pass 19 (`internal/mailcompose/` exists). Same for #43 and
  #12. The pass scope shifts from "apply" to "close out."
- **README scope and shape?** Settled in brainstorm. Polished but
  restrained tone (between Charm and aerc), feature tour first
  with a "what's distinctive" follow-up, wizard-led quickstart,
  high-level architecture, MIT license. Two static screenshots
  side-by-side as the hero. Status section near the top.

## Decision

### README structure

Title + tagline: `# poplar` / *A modern TUI mail client with all
the fixin's.*

Sections in order:

1. **Hero strip** — two side-by-side screenshots (asset paths
   under `docs/assets/`):
   - `two-pane.png` — sidebar + message list + reader with a
     markdown-rendered body
   - `compose.png` — compose surface with catkin's live markdown
     highlighting visible
2. **Status** — beta-soak banner. One short paragraph: "poplar
   is in beta soak. Data formats are frozen at v0.9.0; bug-fix
   releases land until v1.0." Pointer to ADR-0105 and BACKLOG.md.
   Brief "coming in 1.1" line naming native OAuth (#42) and the
   neovim companion (#6).
3. **Feature tour** — framing sentence ("every feature you
   expect from a modern desktop mail client, in 80×24") then
   feature blocks, each one short paragraph:
   - Threaded conversations
   - Cross-folder search (FTS5, operator vocabulary)
   - Compose (catkin editor, contacts autocomplete, attachments,
     scheduled send, undo send, multiple identities + signatures)
   - Contacts (CardDAV sync, T9 sidebar)
   - Attachments (viewer chips, `@` picker, `Ctrl+O` in compose)
   - Outbound delivery (outbox state machine, optimistic UI)
   - Themes (15 built-in, One Dark default, no runtime TOML)
4. **What's distinctive** — five bullets that explain why poplar
   exists alongside aerc/neomutt/alpine:
   - `internal/content` + `internal/filter` (mailrender) —
     lipgloss block model; plain text *and* HTML render through
     one structured pipeline. No glamour, no pandoc.
   - First-class markdown — compose writes markdown, the wire
     carries `multipart/alternative` (text + HTML via goldmark).
   - tidytext — `Ctrl+T` AI rewrite of the current compose
     draft. User-invoked, never silent.
   - Full JMAP — direct on `rockorager/go-jmap`. Atomic
     `Email/import` + `EmailSubmission/set`. Native push.
   - Local cache + outbox — per-account SQLite, background body
     backfill, queue-based op model, offline-tolerant.
5. **Quickstart** — install + first run:
   - `go install github.com/glw907/poplar/cmd/poplar@latest`
   - `poplar` launches the wizard on first run; the wizard
     handles provider selection, credentials, and a connection
     test, then writes `~/.config/poplar/config.toml`
   - **Provider notes** subsection:
     - **Fastmail (JMAP)** — generate an API token at
       fastmail.com, paste into the wizard
     - **Gmail (IMAP)** — XOAUTH2 via `password-cmd` against
       your own OAuth helper for v0.9.0; native OAuth (BYO
       client ID) lands in v1.1 (#42)
     - **Generic IMAP** — presets for iCloud, Yahoo, Zoho,
       Outlook, mailbox.org, Posteo, Runbox, GMX, ProtonMail
       (Bridge); password or `password-cmd`
   - `poplar config check` validates credentials end-to-end
     before the first launch into the UI
6. **Keybindings** — compact table of the ~10 most common keys
   (`j`/`k`, `Enter`, `r`/`R`/`f`, `c`, `D`, `/`, `?`). Pointer
   to `docs/poplar/keybindings.md` for the full map. Note: vim-
   first, modifier-free single keys (no Ctrl/Alt sequences).
7. **Architecture** — single-page overview:
   - Single Go module, single binary (`cmd/poplar`).
   - bubbletea v2 throughout — `charm.land/bubbletea/v2`,
     `lipgloss/v2`, `bubbles/v2`. Elm architecture. Showcase
     build for the v2 stack.
   - Direct on emersion + rockorager: `go-imap` v2, `go-smtp`,
     `go-webdav`, `go-vcard`, `rockorager/go-jmap`. No aerc fork.
   - Modern Go 1.26 — slices/maps/iter/slog (ADR-0196).
   - Pointers to `docs/poplar/system-map.md` and
     `docs/poplar/decisions/INDEX.md` for deeper dives.
8. **Configuration** — short: one file
   (`~/.config/poplar/config.toml`), self-documenting template,
   wizard writes it, hand-edits welcome. Pointer to
   `docs/poplar/styling.md` for the theme list.
9. **Contributing** — pointer to `BACKLOG.md` for issues, mention
   `make check` as the gate. Note that the project is solo-
   maintained pre-1.0; broader contribution norms will land
   alongside `CONTRIBUTING.md` in v1.0 prep (#41).
10. **License** — MIT, pointer to `LICENSE`.

Target length: 250–350 lines of markdown.

## Consequences

**Unlocks.** A public-facing README means the repo can go
public without an evaluator bouncing on the empty `cat README`.
The MIT license unlocks both adoption and contributors. Tag
freezes data formats — schema, config layout, on-disk caches.

**Forecloses.** Anything that would change the on-disk schema
or config format is off the table after tag, except bug-fix
releases on the `v0.9.x` line. New features queue on `1.1`
post-tag. The README's claim of "data formats are frozen" is
load-bearing — it's the user contract for beta soak.

**Follow-ups deferred to v1.0 prep:** `CONTRIBUTING.md` (#41),
GitHub Actions for `make check` (#40), and any package-mirror
work (Homebrew tap, AUR, etc.) — none are blockers for tag.
