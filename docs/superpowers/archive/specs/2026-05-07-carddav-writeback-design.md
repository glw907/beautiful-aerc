# CardDAV write-back — Pass 9m.1

Round-trip the contact-edit Form: form save → cache upsert →
outbox PUT → CardDAV server, plus deletion via the same path.
Builds on 9m's CardDAV ingest (vCard parser, client wrapper,
sync orchestrator, cache contacts table).

## Goals

- `ContactSaveMsg` from the Form lands a new or updated vCard on
  the CardDAV server, optimistically reflected in the cache.
- `D` in the Form (existing-contact only) deletes via the same
  outbox path.
- vCard edits are **lossless**: fields poplar doesn't model
  (BDAY, ADR, IMPP, URL, PHOTO, X-*) survive round-trip.
- Conflict semantics mirror the mail outbox: `If-Match` ETag,
  412 → revert + conflicted state visible in the outbox view.

## Non-goals

- Schema migration (existing columns suffice).
- Multi-book move (changing `SaveTo` across books edits in place
  on the destination book; cross-book move is a separate later
  pass if it ever matters).
- vCard PHOTO editing UI.

## vCard regeneration — patch, not rebuild

On save we **patch the stored vCard blob** rather than rebuild
from the `Contact` projection. Rebuilding would silently strip
every field poplar doesn't model — BDAY, ADR, IMPP, URL,
PHOTO, X-properties — on every edit. Other CardDAV clients (iOS
Contacts, etc.) commonly set those, and a shared address book
that loses them on poplar edits is a serious interop bug.

`contacts.PatchVCard(stored []byte, c Contact, now time.Time) ([]byte, error)`:

- Decodes the stored card with `vcard.NewDecoder`.
- Mutates only the keys poplar owns: FN, N, ORG, TITLE, NOTE,
  EMAIL, TEL, UID (set if absent), REV (always set to
  `now.UTC().Format(time.RFC3339)`).
- All other fields are passed through verbatim.

Email/phone matching during patch:

- **Emails** matched by address equality, case-insensitive.
  Phones matched by E.164 equality (post `phonenumbers.Parse`).
- Rows present in the stored card and in `c` keep their existing
  TYPE/label parameters (preserves iOS quirks like
  `_$!<Work>!$_`).
- Rows present in `c` but not in the stored card are appended
  with our canonical labels ("work" / "home" / "" for emails;
  "mobile" / "work" / "home" / "fax" / "" for phones) as the
  TYPE param.
- Rows present in the stored card but not in `c` are dropped.
- PREF param is re-derived: index 0 in the rebuilt EMAIL/TEL
  list gets `PREF=1`; others get `PREF` cleared.

`contacts.BuildVCard(c Contact, now time.Time) ([]byte, error)`
encodes a minimal card from scratch for new contacts (no
stored blob to patch). Same rules; UID generated by the cache
layer (UUID) before BuildVCard is called.

## Op kinds

`internal/cache/ops.go` adds:

```go
const (
    KindContactPut    OpKind = ...
    KindContactDelete OpKind = ...
)

type ContactPutArgs struct {
    BookHref string
    Href     string // "" for new
    IfMatch  string // "" for new
}
type ContactDeleteArgs struct {
    Href    string
    IfMatch string
}
```

Both implement `OpArgs` via `opKind()`. Outbox `payload` carries
the vCard bytes for `KindContactPut`; nil for `KindContactDelete`.

## Cache surface

`internal/cache/contacts.go` adds:

```go
func (a *Account) QueueContactPut(
    ctx context.Context,
    bookHref string,
    uid string,
    vcardBytes []byte,
) error

func (a *Account) QueueContactDelete(
    ctx context.Context,
    uid string,
) error
```

Both run optimistic local apply + outbox insert in a single
`a.tx`:

- `QueueContactPut` upserts the row (writing the new vCard +
  bumped REV; ETag stays at the old value as the `If-Match`
  pivot), reconciles the recipient projection (see below),
  then inserts the outbox row.
- `QueueContactDelete` looks up href + etag for the row, deletes
  all `message_recipients` rows where `contact_uid = uid`,
  deletes the contact row, inserts the outbox row.

### Recipient projection reconciliation

When emails change on edit, `message_recipients` rows that
point at the old contact via the dropped addresses become
stale — past 9m's initial backfill would re-attribute on the
next full sync, but Pass 9m.1 fixes this inline.

In `QueueContactPut`, before the upsert:

- Read old emails from the existing row (decode stored vCard
  or use cached projection columns).
- Diff against the new `Contact.Emails`.
- For each **removed** address: delete `message_recipients`
  rows where `contact_uid = uid AND address = removed`.
- For each **added** address: insert
  `message_recipients(message_uid, address, contact_uid)`
  rows joined against `messages` whose envelope contains that
  address — same shape as the 9m backfill, scoped to the
  single UID.

Both the diff and the inserts run in the same `a.tx` as the
upsert and the outbox-row insert; one tx per edit.

## Drainer

`internal/cache/drainer.go` gains two dispatch arms:

- `KindContactPut` → `Writer.PutAddressObject(ctx, args.Href,
  args.IfMatch, payload)`. On success, `UPDATE contacts SET
  href=?, etag=? WHERE uid=?`. On `ErrPreconditionFailed`:
  refetch via `Writer.Multiget`, overwrite local row, mark
  outbox conflicted. On `ErrAuth`: mark `auth_error`. Transient
  → existing backoff path.
- `KindContactDelete` → `Writer.DeleteAddressObject(ctx,
  args.Href, args.IfMatch)`. On success, drop the outbox row.
  `ErrNotFound` → success (idempotent, mirrors `mail.Destroy`).
  `ErrPreconditionFailed` → refetch + restore local row + mark
  conflicted. `ErrAuth` → `auth_error`.

`revertOptimisticTx` no-ops on these kinds (refetch is the
revert).

## Client wrapper

`internal/contacts/client.go` adds:

```go
func (c *Client) PutAddressObject(ctx context.Context,
    href, ifMatch string, body []byte) (newHref, newETag string, err error)

func (c *Client) DeleteAddressObject(ctx context.Context,
    href, ifMatch string) error
```

Both build raw `http.NewRequestWithContext` requests on the
existing `httpClient`. `Content-Type: text/vcard; charset=utf-8`
on PUT. `If-Match` set when non-empty. Status mapping:

- 200 / 201 / 204 → success; PUT reads `Location` (or echoed
  href) and `ETag` headers.
- 401 / 403 → `ErrAuth`.
- 404 → `ErrNotFound`.
- 412 → `ErrPreconditionFailed`.
- everything else → wrapped error (transient, drainer backs off).

Sentinels declared in `internal/contacts/client.go`:

```go
var (
    ErrAuth                 = errors.New("contacts: auth")
    ErrNotFound             = errors.New("contacts: not found")
    ErrPreconditionFailed   = errors.New("contacts: precondition failed")
)
```

The cache drainer routes via `errors.Is`.

## UI — Form

`internal/ui/contacts/form.go`:

- New `key.Binding` `Delete` bound to `D`, gated on
  `f.initial.UID != ""`. Visible in help vocab when enabled.
- Pressing `D` returns a cmd emitting
  `OpenContactDeleteConfirmMsg{UID, DisplayName}`.
- Save flow unchanged at the Form layer: still emits
  `ContactSaveMsg{Contact, SaveTo}`.

## UI — App

`internal/ui/app.go`:

- `ContactSaveMsg` handler: resolve `SaveTo` → book href, look
  up the cache row (by UID; UID may be empty for new contacts —
  generate UUID then), read stored vCard. Call
  `PatchVCard` (existing) or `BuildVCard` (new). Call
  `acct.QueueContactPut`. Close the Form.
- `OpenContactDeleteConfirmMsg` handler: open ModalShell
  confirm with copy "Delete contact «name»?". Yes →
  `ContactDeleteMsg{UID}`. No → close confirm, leave Form open.
  Add `pendingContactDelete *contacts.Contact` field; the
  confirm cascade tail picks form-discard before
  contact-delete before compose-save.
- `ContactDeleteMsg` handler: `acct.QueueContactDelete`. Close
  the Form.

  `UID != ""`.
